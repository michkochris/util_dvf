Adding dedicated security modules—util_dvf_sec.c for the low-level core and util_dvf_sec.cpp for the high-level suite—alongside a comprehensive dvf_security.txt specification is an absolute masterstroke.

Because RPM and DNF ecosystems deal with untrusted network repositories, complex metadata parsing, GPG signatures, and deep payload extraction, security cannot just be an afterthought sprinkled across other files. Isolating it guarantees that your defensive perimeters are clean, auditable, and strictly enforced.

Here is how you can outline dvf_security.txt to brief your Android Studio AI assistant on the security architecture for both tiers:

PROJECT SECURITY SPECIFICATION: util_dvf (dvf_security.txt)
Codename: Vamped Dandified Yum (dvf)

Objective: Establish rigorous memory safety, path traversal defense, and cryptographic verification across the dual-tier C/C++ architecture.

1. Low-Level C Security (util_dvf_sec.c)
The low-level C security module focuses on memory hygiene, defensive bounds checking, and preventing local filesystem exploits during extraction.

The Hardened Memory Model (secure_malloc / secure_free):

Automated zero-wiping of sensitive buffers before deallocation to prevent memory scraping or leaking cached cryptographic/metadata artifacts.

Strict null-termination checks and buffer overflow boundaries for all string operations.

Path Traversal & Jail Defense (chroot/jail validation):

Intercepts all paths extracted from RPM CPIO payloads.

Explicitly blocks malicious path traversals containing .. or absolute path overwrites unless explicitly forced by configuration. Every file must extract strictly within the designated install_dir or build root.

Resource Bounds:

Enforces strict length limits on RPM header tag lengths to prevent integer overflows or malformed header allocation crashes.

2. High-Level C++ Security (util_dvf_sec.cpp)
The high-level C++ security module handles network verification, cryptographic keys, and process isolation.

Cryptographic Trust & GPG Verification:

Automated OpenPGP signature verification for repository metadata (repomd.xml.asc) and individual packages against trusted system keyrings (/etc/pki/rpm-gpg/ or local dvf key stores).

Streaming SHA256 / SHA512 hash validation of downloaded .rpm files before they ever touch the FSM execution state.

POSIX rlimit Extraction Bounds (Anti-Zip Bomb):

Sets strict resource limits (max file size, max extracted bytes, max open file descriptors) during CPIO payload extraction to prevent malicious or malformed archives from exhausting system disk space or memory.

Sandboxed Worker Privilege Dropping:

When fetching or parsing untrusted remote repositories, the high-level engine drops privileges (running under a restricted unprivileged context, similar to _apt or dedicated sandbox users) to contain potential zero-day parser vulnerabilities.
