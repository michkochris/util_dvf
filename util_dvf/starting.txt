PROJECT SPECIFICATION & ARCHITECTURAL BLUEPRINT: util_dvf
Codename: Vamped Dandified Yum (dvf)

Paradigm: Strict Finite State Machine (FSM) Driven Execution

1. Executive Summary & Design Philosophy
util_dvf brings the lightning-fast, zero-dependency, modular design principles of runepkg into the notoriously complex world of RPM and DNF ecosystems. Because RPM package headers, CPIO payloads, and DNF repository metadata (repomd.xml, primary sqlite/xml databases) carry immense structural complexity, util_dvf must be built as a strict Finite State Machine (FSM) from day one.

By piggybacking on runepkg’s proven cascading configuration patterns and binary autocompletion architecture, util_dvf will cut through traditional DNF bloat while maintaining absolute transactional integrity.

2. Core File Structure (util_dvf/)
The initial bootstrap consists of four core modular components designed to mirror your trusted architecture:

Plaintext
util_dvf/
├── util_dvf_config.c     # Cascading configuration parser (piggybacked on runepkg config system)
├── util_dvf_auto.c       # Binary-serialized autocompletion engine (mmap index for RPM repos)
├── util_dvf_cli.c        # Interleaved command dispatcher with early --verbose tracing
└── util_dvf_fsm.c        # The core Finite State Machine transaction engine
3. Component Specifications
A. util_dvf_config.c (Configuration Layer)
Objective: Inherit and adapt the cascading configuration system from runepkg.

Key Variables: Plain-English, clean keys like library_path=, install_dir=, rpm_db_path=, and repository base URLs.

Behavior: Reads from /etc/dvf/dvfconfig or falls back to standard environment overrides (DVF_CONFIG_PATH). It strips out legacy configuration bloat to keep parsing near-instantaneous.

B. util_dvf_cli.c (Interleaved Command Dispatcher)
Objective: Handle complex, multi-action command lines seamlessly (e.g., dvf -v -i pkg1.rpm -s pkg2 -i pkg3.rpm).

Early Verbosity: --verbose (and -d debug) flags must be parsed in the first execution pass before any state transition occurs, ensuring every internal FSM step is fully traceable right from process startup.

C. util_dvf_auto.c (High-Speed Autocompleter)
Objective: Deliver lightning-fast shell autocompletion (complete -o nospace -C util_dvf util_dvf).

Mechanism: Utilizes memory-mapped (mmap) binary indices (dvf_autocomplete.bin) to serve command-line options, installed RPM states, and remote repository packages with zero flat-file parsing bottlenecks.

D. util_dvf_fsm.c (The FSM Transaction Engine)
Objective: Guarantee transactional safety, atomic state changes, and safe rollbacks across complex multi-package RPM operations.

State Lifecycle:

STATE_IDLE: Initialization and configuration load.

STATE_RESOLVING: Dependency graphing and header fetching.

STATE_VERIFYING: GPG signature and checksum validation (SHA256/MD5).

STATE_TRANSACTION_PREP: Locking RPM database and staging payloads.

STATE_EXECUTING: Unpacking CPIO payloads and updating local db state.

STATE_COMMITTED / STATE_ROLLED_BACK: Finalizing logs or recovering from faults.
